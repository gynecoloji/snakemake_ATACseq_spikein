# Executable test case (`.test/`)

A complete, self-contained run of the workflow on a synthetic miniature dataset.
It executes every stage for real — alignment, spike-in extraction, duplicate
removal, peak calling, consensus, counting, QC, differential openness — and then
**asserts the numbers that come out**, not merely that files appeared.

Runs in a few minutes on one core. Nothing is downloaded.

## Running it

```bash
python .test/make_testdata.py       # regenerate inputs (optional; they are committed)
snakemake -s workflow/Snakefile \
  atacseq_all results/qc/tss_enrichment_scores.tsv \
  -d .test --sdm conda -c 4
python .test/assert_outputs.py      # the actual test
```

The TSS table is requested explicitly rather than through `qc_all`, because it is what the
phantom-`bins` check reads, while the rest of `qc_all` pulls in `computeGCBias`, which needs
a `.2bit` the fixture does not build.

`assert_outputs.py` exits non-zero if any assertion fails. That is what CI gates on.

## Why it asserts values

The expected outputs are known **by construction** — `make_testdata.py` plants
them with a fixed seed (`SEED = 20260801`) — rather than being recorded from a
previous run and frozen. A recorded baseline only tells you the output changed;
a constructed one tells you it is *wrong*.

Two things are planted and checked:

| Planted | Asserted |
|---|---|
| Spike-in fraction per sample (10 % / 11 %) | recovered per sample; within-condition spread ≤ 2× |
| 40 accessible regions on `chr21` | ≥ 20 peaks called, all on `chr21`, ≥ 20 regions in the count matrix |
| 10 of those 40 are 4× stronger in Treatment | differential table has `padj` / `log2FoldChange` and tests the regions |
| 4 samples, no others | TSS table has exactly 4 rows — **no phantom `bins` row** |

That last row is a regression test for a real defect: the deepTools TSS parser
skipped one header line where the format has two, so a row literally named `bins`
was emitted and carried downstream as if it were a fifth sample. File-existence
checks did not catch it for as long as it was there.

This matters because it is not what comparable pipelines do. nf-core/atacseq's CI
describes itself as running "with the minimal test dataset to check that it
completes without any syntax errors". nf-core/cutandrun — a JOSS-accepted
pipeline with swappable spike-in normalization — covers each of its five
normalization modes by asserting that one bedGraph file exists. Neither would
have caught the phantom `bins` row, spike-in factors computed from 20 reads, or a
differential stage that was silently unreachable. All three were real here.

## The synthetic dataset

Generated by `make_testdata.py` — deterministic, no external downloads:

- **Genome** `chr21`, 400 kb of random sequence; spike-in contig `2L`, 120 kb.
  Small enough that `bowtie2-build` finishes in seconds, large enough for MACS2
  to model a background.
- **Reads** 60 000 human pairs per sample, 70 % in peaks / 30 % uniform
  background, plus spike-in pairs at the planted fraction. 50 bp, fragments
  120–300 bp.
- **Annotation** one transcript per peak; promoters over the first 20 peaks,
  enhancers over the last 20, so the promoter/enhancer split has both classes
  populated. CTCF anchors are drawn from the **non**-differential peaks, so the
  `ctcf` normalization mode has genuinely invariant anchors.

Spike-in fractions are deliberately tight within each condition (0.10 / 0.11),
because the workflow now refuses to normalize when within-condition spike-in
spread exceeds 2×. The fixture is built to pass its own guard.

## Contents

| Path | What |
|---|---|
| `make_testdata.py` | generates everything below `ref/` and `data/` |
| `assert_outputs.py` | the assertions; non-zero exit on failure |
| `config/config.yaml` | config for the miniature genome (`effective_genome_size: 400000`) |
| `config/samples.csv` | 4 samples, 2 groups × 2 replicates |
| `data/*.fastq.gz` | synthetic paired-end reads |
| `ref/*` | synthetic genomes, GTF, blacklist, promoter/enhancer/CTCF BEDs |

## Also the catalog tube map

The [Snakemake Workflow Catalog](https://snakemake.github.io/snakemake-workflow-catalog/)
renders the rule graph from this same directory:

```bash
snakemake -s workflow/Snakefile -c 1 -d .test --forceall --rulegraph
```

That resolves the DAG only and executes nothing, so it works whether or not the
data has been generated. The sample sheet uses two 2-replicate groups so the
IDR-dependent rules appear in the map.
